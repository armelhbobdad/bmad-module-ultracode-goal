## ATDD red-phase contract

- Every test is designed to fail before implementation; exactly one red-phase scaffold per criterion, built on its smallest criterion-defining assertion. [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-03-test-strategy.md:L78] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-03-test-strategy.md:L43] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-03-test-strategy.md:L44] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04a-subagent-api-failing.md:L143]
- Scaffolds carry `test.skip()` in every execution mode; each leaf title has one id: `[P#] AC-<n> description`. [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04-generate-tests.md:L362] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04a-subagent-api-failing.md:L34] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04a-subagent-api-failing.md:L142]
- E2E scaffolds wrap the journey in one `expect(...).resolves.toBeUndefined()`. [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04b-subagent-e2e-failing.md:L194]
- Aggregation throws on a file without `test.skip()` or a placeholder assertion such as `expect(true).toBe(true)`, and never removes `test.skip()`. [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04c-aggregate.md:L97] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04c-aggregate.md:L101] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04c-aggregate.md:L24]
- Worker registries must match the step-1 registry; worker JSON marks tests `expected_to_fail: true`. [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04c-aggregate.md:L69] [SRC:src/workflows/testarch/bmad-testarch-atdd/steps-c/step-04a-subagent-api-failing.md:L255]
- GREEN phase: the developer removes `test.skip()` for one test and confirms it fails first. [SRC:src/workflows/testarch/bmad-testarch-atdd/atdd-checklist-template.md:L273]

## Shared execution-mode resolution

ATDD step 4, automate step 3, test-design step 5, NFR step 4, test-review step 3 and trace step 4 resolve `tea_execution_mode` (default `auto`) and `tea_capability_probe` (default `true`) the same way: an explicit request in the run wins; `auto` picks agent-team, then subagent, then sequential; with probing off an unexecutable mode fails with an explicit error.
