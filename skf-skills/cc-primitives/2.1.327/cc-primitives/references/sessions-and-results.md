## Session identity

- `claude -p --output-format json` prints the result, the session ID and metadata (the default `text` format is plain text); for a non-interactive run, the ID to pass to `--resume` is the `session_id` field of that output. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/errors]
- `session_id` is present on every Agent SDK result message, success or error; in TypeScript it is also a direct field of the init system message, in Python it is nested in `SystemMessage.data`. Connection or process failures yield no result message, so no `session_id` arrives that way. [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]
- A `claude -p` run stopped with SIGTERM exits `143` and records no result for the turn in progress. [EXT:https://code.claude.com/docs/en/headless]
- In `stream-json` output, system events such as `system/api_retry` and `system/plugin_install` carry `session_id`, the session the event belongs to. [EXT:https://code.claude.com/docs/en/headless]
- `--session-id <uuid>` uses a specific session ID for the conversation; the value must be a valid UUID. [EXT:https://code.claude.com/docs/en/cli-reference]
- `--name` / `-n` sets a display name shown in `/resume` and the terminal title; a named session resumes with `claude --resume <name>`. [EXT:https://code.claude.com/docs/en/cli-reference]
- Unnamed sessions get two labels, and only the generated title works as a resume handle: the default display name (interactive sessions, such as `my-app-3f`, also shown in `claude agents --json` output) is not one, and a `claude -p` run started directly from a shell or script gets no generated title. [EXT:https://code.claude.com/docs/en/sessions]
- `CLAUDE_CODE_SESSION_ID` is set to the current session ID in Bash and PowerShell tool, hook command and stdio MCP server subprocesses. For Bash, PowerShell and hooks it matches the hook input `session_id` and is updated on `/clear`. An MCP server subprocess keeps the ID it was spawned with: it receives the resumed ID on `--resume <session-id>`, but on `--continue` or `--resume` without an explicit ID it may receive the initial startup ID. [EXT:https://code.claude.com/docs/en/env-vars]

## Resume and continue

- Under `-p`, `--continue` continues the most recent conversation and `--resume <session-id>` a specific one; `--resume` also takes a session name or the absolute path to a session's `.jsonl` transcript. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/cli-reference]
- Starting or continuing a conversation with `-p` needs a prompt, as an argument or piped on stdin; it can be skipped when a `SessionStart` hook supplies `initialUserMessage` or when the resumed session has a deferred tool call. [EXT:https://code.claude.com/docs/en/hooks]
- `--continue` picks the most recent session recorded under the directory you launch from, including sessions that added that directory with `/add-dir`. Plain `claude --continue` skips `-p`, Agent SDK and first-prompt `/loop` sessions; `claude -p --continue` includes them. [EXT:https://code.claude.com/docs/en/worktrees] [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/sessions]
- From v2.1.257, `--continue` opens a background session that has finished, but not one still running; when the most recent conversation is one you moved to the background and it is still running there, `claude --continue` exits with `Your most recent conversation is running in the background` and that session's ID. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/sessions]
- `-p` and SDK sessions stay out of the session picker but resume by ID, and the run that created the session and the `-p --resume <id>` run may start in different directories. The ID is searched in the current project directory and its git worktrees, then in every other project on the machine (from v2.1.223; before, only the first). The cross-project search resolves only when exactly one other project holds a transcript with messages for the ID, so a hand-copied duplicate reports not-found. [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/cli-reference]
- A name resolves across the current repository and its worktrees (plus sessions that added the directory with `/add-dir`); an exact match resumes directly, even in another worktree, and an ambiguous `claude --resume <name>` opens the session picker with the name pre-filled. [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/cli-reference]
- No match prints `No conversation found with session ID: <session-id>` and exits `1`. Common causes: a mistyped ID, a transcript the retention sweep removed, a different machine (transcripts are stored locally), or duplicate copies. [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/errors]
- `--fork-session`, used with `--resume` or `--continue`, creates a new session ID: the fork starts from a copy of the history, the original stays unchanged and both can be resumed separately. The forked process starts without the original's "Allow for this session" grants. [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]
- In the Agent SDK, forking branches the conversation history, not the filesystem: a forked agent's file edits are real and visible to any session working in the same directory. [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]
- Two `claude -p` runs that resume the same session at the same time both write to one transcript, and messages from one can be missing when that session is resumed later; add `--fork-session` to each command to keep both. [EXT:https://code.claude.com/docs/en/sessions]
- Background session still running: from v2.1.285, `claude -p --resume <session> "prompt"` typed at a terminal attaches to it and sends the prompt as its next turn. With piped or redirected input or output, flags that configure the session (such as `--permission-mode`, `--model` or `--settings`), flags that read the output (such as `--output-format json` or `--json-schema`), flags that limit or rewind the run (such as `--max-turns` or `--max-budget-usd`), or agent view turned off, it sends nothing and exits `1`; add `--fork-session` to resume a copy, or run `claude stop <id>` and repeat the command. Before v2.1.285, Claude Code refused. See [Worktrees and background sessions](worktrees-and-background.md). [EXT:https://code.claude.com/docs/en/sessions]
- A run that ended with `error_max_turns` or `error_max_budget_usd` can be resumed by session ID with a higher limit (Agent SDK). [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]

What a resume restores when Claude Code loads the conversation from its transcript: [EXT:https://code.claude.com/docs/en/sessions]

| State | On resume |
|-------|-----------|
| History | Messages, tool calls and results; after compaction, the last compaction's summary, the messages it left unsummarized and every later message (the summarized messages are not loaded again) [EXT:https://code.claude.com/docs/en/sessions] |
| Permission mode under `-p` | Not restored, apart from plan mode (next row): the run starts in the permission mode a new `claude -p` run would start in [EXT:https://code.claude.com/docs/en/sessions]; for a resumed deferred session, pass `--permission-mode` or `--dangerously-skip-permissions` again if the session used one ([Permission modes](goal-and-permissions.md#permission-modes)) [EXT:https://code.claude.com/docs/en/hooks] |
| Plan mode under `-p` | Restored (v2.1.246+) only when all hold: `--permission-prompt-tool` is passed without `--permission-prompts none`; `permissions.denyInsteadOfPrompting` is off; none of `--permission-mode`, `--dangerously-skip-permissions`, `--fork-session` is passed; the run isn't started through channels; no deny rule removes `ExitPlanMode` [EXT:https://code.claude.com/docs/en/sessions] |
| Model | The model the session was using, except in the cases listed on the model-config page [EXT:https://code.claude.com/docs/en/sessions] |
| Agent | A session started with `--agent` or the `agent` setting continues as that agent with its tool restrictions and model, looked up in the original directory (if that workspace is trusted), then in the directory you resume from; found in neither, it resumes with default tools and a warning (a non-interactive resume also prints it to stderr; sessions using `--input-format stream-json` don't show it; before v2.1.216, it continued silently as the default agent and searched only the directory you resume from); `--agent` on resume picks another [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/errors] |
| System prompt | The prompt recorded on the first request is reused until compaction; different system prompt flag text, or none, takes effect after compaction or in a new conversation; `--system-prompt-snapshot off` (v2.1.257+) rebuilds it on every request; in bare mode outside cloud sessions, recording stays off unless `--system-prompt-snapshot on`; before v2.1.265, passing any system prompt flag also turned recording off unless `--system-prompt-snapshot on` [EXT:https://code.claude.com/docs/en/cli-reference] |
| Launch flags | Not restored: pass flags such as `--mcp-config`, `--plugin-dir`, `--add-dir` (also for directories added with `/add-dir`), `--settings` and `--fallback-model` again, except when reopening a running background session or resuming a stopped one by full session ID with `--bg` [EXT:https://code.claude.com/docs/en/sessions] |
| Worktree | A session that ended inside a worktree without exiting it returns there, `-p` and Agent SDK resumes included (non-interactive from v2.1.212; before, it stayed in the starting directory); a `--fork-session` fork starts in the launch directory and leaves the original's worktree untouched; a deleted worktree resumes in the launch directory with a notice and the binding cleared [EXT:https://code.claude.com/docs/en/worktrees] |
| Goal | An active goal carries over on every resume route (the `claude --resume` picker from v2.1.239) with its turn count, timer and token-spend baseline reset; a goal already achieved or cleared is not restored [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/goal] |
| Scheduled tasks | Unexpired session-scoped tasks are restored; background Bash and monitor tasks are not [EXT:https://code.claude.com/docs/en/sessions] |
| Interrupted tool call | A tool still running when the previous process ended, for example in a crash, is not rerun [EXT:https://code.claude.com/docs/en/sessions] |
| Background work | Background subagents, Bash commands or workflows that ended with the previous process show as not-finished notes; no turn starts from them, Claude reads them with the next prompt [EXT:https://code.claude.com/docs/en/sessions] |

- Before returning a session to its worktree, Claude Code verifies that the worktree is still a separate checkout. Under `-p` and Agent SDK resumes, every refusal except a gone worktree stops the resume with a stderr error instead of continuing without isolation; with `stream-json` the refusal also arrives as a `result` message with subtype `error_during_execution` and the text in `errors` (v2.1.260+). Messages and recoveries: [Worktrees and background sessions](worktrees-and-background.md). [EXT:https://code.claude.com/docs/en/worktrees]
- SIGTERM ends a `-p` run with exit `143` and leaves the turn in progress unfinished with no result; Claude Code terminates a running Bash command's process tree (recorded as killed), runs `SessionEnd` hooks and exits. Send SIGINT, or call the Agent SDK's `interrupt()`, first to end the turn instead. [EXT:https://code.claude.com/docs/en/headless]
- On resume, an interrupted turn is left as it is and the next prompt drives the conversation, unless `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` is set, which continues a session that ended mid-turn without re-sending the prompt. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/env-vars]
- `CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS` (v2.1.211+) is the maximum age of the last transcript message for that automatic continuation; past it, the session starts idle. Unset or `0` sets no bound, except that some turns, such as one that ended with an API error, continue only within six hours; a positive value bounds every turn; a negative or non-numeric value applies a one-hour bound. [EXT:https://code.claude.com/docs/en/env-vars]
- `CLAUDE_CODE_RESUME_PROMPT` replaces the continuation message (default `Continue from where you left off.`; an empty string uses the default) for an interrupted-turn continuation and for a `-p` resume of a deferred tool call. `CLAUDE_CODE_RESUME_SHOWS_CUT_OFF_CALLS=1` (v2.1.309+) keeps interrupted tool calls, marked as cut off, in a continued turn; when unset they are dropped, and some calls stay dropped, such as calls to subagents, skills, workflows and tools that wait on a person. [EXT:https://code.claude.com/docs/en/env-vars]

## Session storage

- By default, transcripts are JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is the working directory path with non-alphanumeric characters replaced by `-`, truncated to 200 characters plus a hash of the full path when longer. [EXT:https://code.claude.com/docs/en/sessions]
- The entry format is internal and changes between versions, so scripts that parse the files can break on any release; build on `/export` or the script interfaces instead: `-p` `json` or `stream-json` output, `claude -p --resume <session-id>`, the `transcript_path` field that hooks and status line commands receive, or the Agent SDK. [EXT:https://code.claude.com/docs/en/sessions]
- `CLAUDE_CONFIG_DIR` moves storage off `~/.claude`; sessions are then under `$CLAUDE_CONFIG_DIR/projects/`. [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]
- `CLAUDE_CODE_PROJECT_DIR_NAME` (v2.1.234+) names the directory under `projects/` (the `<project>` part) that holds the session's transcripts and auto memory, whatever the working directory. It is ignored unless `CLAUDE_CONFIG_DIR` is set; it takes 1 to 64 letters, digits, hyphens or underscores (not a Windows device name; any other value falls back to the derived name); it is read once at startup from the launching environment, never from a settings `env` block. A later launch with the same `CLAUDE_CONFIG_DIR` but without it uses the derived directory again, and `claude --resume <session-id>` finds a session stored under either name. [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/env-vars]
- Retention is `cleanupPeriodDays` (any settings file; whole days, minimum `1`, default `30`; `0` fails validation, so use a large value such as `3650` for long retention). Deletion runs as a background sweep after a session starts, as long as the retention period can be safely determined, and shows no message; a swept session's `--resume <id>` reports not-found. [EXT:https://code.claude.com/docs/en/settings-reference] [EXT:https://code.claude.com/docs/en/errors]
- `claude purge` deletes a project's transcripts and related state sooner; deleting a background session with `claude rm <id>` keeps its transcript, which stays resumable. [EXT:https://code.claude.com/docs/en/sessions]
- `--no-session-persistence` (print mode only) keeps the session off disk, so it cannot be resumed. `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1` skips prompt history and transcripts in any mode, and such sessions do not appear in `--resume`, `--continue` or up-arrow history. [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/env-vars]
- `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC=1` (v2.1.287+) limits a long `-p` or Agent SDK transcript: after each compaction, once the file is larger than 5 MB, the history before that compaction is removed (from v2.1.296, not when that would shrink the file by less than 10%), and resuming restores the same conversation. Set it in the launching environment; a settings `env` block can't turn it on. [EXT:https://code.claude.com/docs/en/env-vars]
- Moving directories: `/cd` relocates a session to the new directory's project storage; when Claude enters or exits a worktree that Claude Code created with git, the session is recorded under the new working directory (a worktree a `WorktreeCreate` hook created keeps it at the launch directory). [EXT:https://code.claude.com/docs/en/sessions] [EXT:https://code.claude.com/docs/en/worktrees]
- Other machines: transcripts are local, so resume on the machine where the session ran. For the Agent SDK, the docs describe persisting `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl` and restoring it inside any directory under `~/.claude/projects/` on the new host before resuming. [EXT:https://code.claude.com/docs/en/errors] [EXT:https://code.claude.com/docs/en/agent-sdk/sessions]

## Result JSON

`--output-format json` returns the result, session ID and metadata, usage and cost included; a `stream-json` run ends with a `result` message holding the final response text, cost and session metadata. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/sessions] Rows citing an `agent-sdk/` page come from the Agent SDK's description of its result message.

| Field | Meaning |
|-------|---------|
| `result` | Final text answer; a failure inside the run, such as missing authentication, is printed as the result on stdout [EXT:https://code.claude.com/docs/en/headless] |
| `session_id` | The ID to pass to `--resume` [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/errors] |
| `subtype` | `success` or an error subtype; named values are `error_max_turns`, `error_max_budget_usd` and `error_during_execution` [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] [EXT:https://code.claude.com/docs/en/agent-sdk/sessions] [EXT:https://code.claude.com/docs/en/hooks] |
| `structured_output` | With `--json-schema`, the schema-conforming output; absent when the run ends without valid structured output, for example when Claude declined the request [EXT:https://code.claude.com/docs/en/headless] |
| `usage` | Cumulative `input_tokens`, `output_tokens`, `cache_creation_input_tokens` (new cache entries, billed above standard input) and `cache_read_input_tokens` (reads from existing entries, billed at a reduced rate); counts only the top-level agent loop [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] |
| `usage.cache_creation` | Splits cache writes into `ephemeral_1h_input_tokens` (one-hour TTL) and `ephemeral_5m_input_tokens` (five-minute TTL) [EXT:https://code.claude.com/docs/en/prompt-caching] |
| `total_cost_usd` | Estimated cost, subagent requests included [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] |
| `modelUsage` | Map of model name to `costUSD`, `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens` and `costBasis` (`list`, `managed` for a `modelPricing` table, or `unknown`; v2.1.246+); subagent requests included [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] |
| `duration_api_ms` | Named among the fields that include work done while the result waits for background subagents [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] |
| `stop_reason` | `tool_deferred` when a `PreToolUse` hook deferred the call (subtype `success`); `tool_deferred_unavailable` when the deferred call's tool isn't available in the resumed session [EXT:https://code.claude.com/docs/en/hooks] |
| `deferred_tool_use` | The deferred call's `id`, `name` and `input` [EXT:https://code.claude.com/docs/en/hooks] |
| `permission_denials` | With `--permission-prompts none` and `stream-json`, the final result lists the denials [EXT:https://code.claude.com/docs/en/headless] |
| `errors` | Error text array; documented for a worktree-resume refusal in `stream-json` (subtype `error_during_execution`, v2.1.260+) [EXT:https://code.claude.com/docs/en/worktrees] |
| `startup_failure_reason` | In the `stream-json` result: `worktree_unverified` or `worktree_resume_refused` for worktree-resume failures, to branch on instead of error text (v2.1.274+) [EXT:https://code.claude.com/docs/en/worktrees] |

- Exit status: `0` on success, non-zero when the run fails; invalid flags are reported on stderr before the run starts. [EXT:https://code.claude.com/docs/en/headless]
- An invalid `--json-schema` exits with `Error: --json-schema is not a valid JSON Schema` and the validator's diagnostic; the `format` keyword is accepted as an annotation and not enforced. [EXT:https://code.claude.com/docs/en/headless]
- When background work starts another turn, `json` prints only the last turn's result and `text` prints each turn's result (v2.1.295+; before, `text` also printed only the last). [EXT:https://code.claude.com/docs/en/headless]
- `error_during_execution` also covers a crash: the process emits a final `error_during_execution` result that may carry zeroed `usage`, `total_cost_usd` and `modelUsage` (Agent SDK). With `permissions.denyInsteadOfPrompting` (v2.1.319+) in auto mode, the turn ends after 20 calls in a row that the classifier blocked or a safety check refused, and a `-p` run reports it as `error_during_execution`. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] [EXT:https://code.claude.com/docs/en/settings-reference]
- `CLAUDE_CODE_STARTUP_FAILURE_RESULTS=1` (v2.1.274+) makes a `stream-json` session write a result message naming why Claude Code refused to start, for startup failures that otherwise end with stderr alone. [EXT:https://code.claude.com/docs/en/env-vars]
- Deferred calls: `defer` is honored only under `-p` with a single tool call in the turn; the pending call stays in the transcript with no timeout until the retention sweep, and `claude -p --resume <session-id>` with the same permission host fires `PreToolUse` again. With `tool_deferred_unavailable`, while the call is pending `result` starts with `<tool> isn't available, so its deferred call didn't run.` (dropping the call writes that result with an empty `result` field); from v2.1.319 (before, a prompt was answered and the call dropped), a prompt sent while the call is pending doesn't reach Claude and the run exits `1`, and `CLAUDE_CODE_DROP_UNAVAILABLE_DEFERRED_TOOL=1` with a prompt drops the call. Round trip: [Defer and resume in -p](hooks.md#defer-and-resume-in--p). [EXT:https://code.claude.com/docs/en/hooks]

## stream-json events

- Each line is one JSON event; the last line is the `result` message. Before exiting, Claude Code waits for a slow consumer to drain the queued output, scaling the wait with how much is queued, capped at 30 seconds. [EXT:https://code.claude.com/docs/en/headless]
- `system/init` reports the model, tools, MCP servers and loaded plugins. It is the first event unless startup events precede it: `plugin_install` events when `CLAUDE_CODE_SYNC_PLUGIN_INSTALL` is set, and `hook_started`, `hook_progress` and `hook_response` events while a `SessionStart` or `Setup` hook runs. [EXT:https://code.claude.com/docs/en/headless]
- `system/init` fields: `plugins` (`name`, `path`); `plugin_errors` (`plugin`, `type`, `message`, plus `path` for a failed `--plugin-dir` from v2.1.283; omitted when empty); `mcp_servers` (`name`, `status`; a remote server with a cached tool list shows `pending`); `mcp_server_errors` (`name`, `type`, `message`; omitted when empty); optional `capabilities` strings such as `interrupt_receipt_v1`, to feature-detect instead of comparing versions, ignoring unknown values. [EXT:https://code.claude.com/docs/en/headless]
- `system/api_retry` precedes each retry of a retryable error, with `attempt` (from 1), `max_retries`, `retry_delay_ms`, `error_status` (HTTP status, or `null` without a response), optional `no_response` (`waited_ms`, `retry_wait_ms`; v2.1.261+), `error` (`authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `billing_error`, `rate_limit`, `overloaded`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `cloud_credential_error` or `unknown`), `uuid` and `session_id`. From v2.1.246, when a `401` or `403` rejects an `apiKeyHelper` credential, the first two retries emit no event but still count toward `attempt`. Retry settings: [Limits and caching](limits-and-caching.md). [EXT:https://code.claude.com/docs/en/headless]
- `system/plugin_install` (with `CLAUDE_CODE_SYNC_PLUGIN_INSTALL`) carries `status` (`started`, `installed`, `failed`, `completed`), `name` and `error` where they apply, `uuid` and `session_id`. [EXT:https://code.claude.com/docs/en/headless]
- Partial messages: `--include-partial-messages` requires `--print` and `--output-format stream-json`; the documented token stream passes `--verbose` too, and text deltas are events with `type` `stream_event` and `.event.delta.type` `text_delta`, read from `.event.delta.text`. [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/headless]
- Subagent and forked-skill messages are `assistant` and `user` messages whose `parent_tool_use_id` names the Agent or Skill `tool_use` that started them (`null` for the main conversation); a forked skill passed as a `/<skill-name>` prompt uses a `forked-command-` value and its messages arrive after it finishes (v2.1.287+). By default the run's `tool_use` and `tool_result` blocks are forwarded; `--forward-subagent-text` or `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT` (both v2.1.211+) adds text and thinking blocks. Other cases have their own version minimums. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/env-vars]
- With `--permission-prompts none` (v2.1.259+), denials appear as `permission_denied` system messages; under `permissions.denyInsteadOfPrompting`, the runs that emit one report `decision_reason` `no approval surface in this session; permission request denied automatically`. [EXT:https://code.claude.com/docs/en/headless] [EXT:https://code.claude.com/docs/en/settings-reference]
- `--include-hook-events` adds hook lifecycle events and requires `--output-format stream-json`; `SessionStart` and `Setup` hook events are always included. [EXT:https://code.claude.com/docs/en/cli-reference]
- The stderr line `Waiting for background work to finish` never lands in the `json` or `stream-json` output a script reads. If the working directory is deleted mid-session, a turn that starts while it is missing emits a warning message in `stream-json` and shell commands fail until it exists again. [EXT:https://code.claude.com/docs/en/headless]

## Cost and usage accounting

- `total_cost_usd` is the cumulative estimated cost across all steps of the call; success and error results both carry it and `usage`. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- `total_cost_usd` and `costUSD` are client-side estimates, not billing data: computed locally from a price table bundled at build time unless a `modelPricing` table is in effect, they can drift when pricing changes, the installed SDK version doesn't recognize a model, or billing rules apply that the client cannot model. Don't bill end users or trigger financial decisions from them. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- The SDK multiplies the list price of a response's tokens by 1.1 when its `usage` reports `inference_geo: "us"`, but not per-request fees such as web search (TypeScript Agent SDK v0.3.239+, Python Agent SDK v0.2.144+). [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- `modelPricing` (managed settings only, ignored in user, project and local settings and `--settings`; v2.1.242+) applies contracted rates to `/usage`, the status line, the Agent SDK's `total_cost_usd`, the `--max-budget-usd` limit and the OpenTelemetry cost metric and events; unset, figures are at list price unless a host application supplies a table. [EXT:https://code.claude.com/docs/en/settings-reference]
- For Pro, Max and Ultra subscribers, usage is included in the subscription, so the `/usage` Session block's session cost figure isn't relevant for billing. [EXT:https://code.claude.com/docs/en/costs]
- Subagents: `usage` excludes them (top-level loop only), while `total_cost_usd` and `modelUsage` include them; use `modelUsage` for whole-tree token accounting. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- Per-step usage sits on each assistant message (TypeScript `message.message.usage`, Python `message.usage`); messages of one turn with several tool calls share an ID, so deduplicate by ID. Per-step `output_tokens` is the `message_start` placeholder: read output tokens from the result's `usage` or `modelUsage`. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- On `error_max_budget_usd`, `usage` leaves out the response that crossed the budget while `total_cost_usd` and `modelUsage` include it. A crash result may be zeroed: recover totals from the result of the turn before the crash when one can help (it cannot in a single-shot call, after a crash on the first turn, or when that turn was the `/clear` itself), otherwise sum per-step `usage` (main-loop input and cache tokens only). [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- In single message input mode, the result waits for background subagents still running at the end of the final turn (up to the background-wait cap), and its `total_cost_usd`, `duration_api_ms` and `modelUsage` include that work. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- Across resumes: session totals are saved to the transcript when the process exits normally and restored when a later call resumes or forks the session. From v2.1.277, each result already includes the earlier spend, so read the latest result rather than summing; before v2.1.277, a session resumed through the SDK or `claude -p` restarted its totals at zero. Independent calls each cover only themselves. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking] With `--output-format json`, a run that continues a conversation with `--continue` or `--resume` reports the conversation's whole total, earlier runs' spend included. [EXT:https://code.claude.com/docs/en/headless]
- `--max-budget-usd` (print mode only) is checked against the client-side estimate; subagent spend counts, spend can pass the cap, and totals restored by `--continue` or `--resume` don't count. Once the cap is reached, spawning another subagent fails with `Budget limit reached` and running background subagents stop (v2.1.217+), and at exit the remaining background work is stopped instead of awaited. [EXT:https://code.claude.com/docs/en/cli-reference] [EXT:https://code.claude.com/docs/en/headless]
- Agent SDK streaming input mode: each turn's result `usage` covers that turn's main loop only, while `total_cost_usd` and `modelUsage` are running totals for the call plus restored spend; `/clear`, `/reset` and `/new` restart them, and the `/clear` turn's result carries a new `session_id`. [EXT:https://code.claude.com/docs/en/agent-sdk/cost-tracking]
- A resume sends the whole conversation again and reads from the cache only the unchanged prefix still within the cache lifetime; TTLs are in [Limits and caching](limits-and-caching.md). [EXT:https://code.claude.com/docs/en/prompt-caching]
