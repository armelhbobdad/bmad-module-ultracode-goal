## bmad-code-review

Reviews code changes with several independent reviewers in parallel, then triages and presents findings; triggered by "run code review" or "review this code". [SRC:src/bmm-skills/ship/bmad-code-review/SKILL.md:L3] [SRC:src/bmm-skills/ship/bmad-code-review/SKILL.md:L3] It loads `_bmad/bmm/config.yaml`, resolves `sprint_status` as `{implementation_artifacts}/sprint-status.yaml`, and loads any `project-context.md` it finds. [SRC:src/bmm-skills/ship/bmad-code-review/SKILL.md:L44] [SRC:src/bmm-skills/ship/bmad-code-review/SKILL.md:L49] [SRC:src/bmm-skills/ship/bmad-code-review/SKILL.md:L50]

**Target selection (step-01).** Tier 1 accepts an explicit PR (resolved with `gh pr view`), commit SHA, branch, spec file (its `baseline_commit` becomes the diff baseline) or diff source; keywords select uncommitted (`git diff HEAD`) or branch diffs (three-dot against the base; a missing base HALTs). [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L22] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L23] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L25] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L28] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L29] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L63] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L64] Tier 3 scans sprint-status for stories in `review`. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L38] No target HALTs; an empty diff HALTs. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L54] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L68] `review_mode` is `full` or `no-spec`; `no-spec` is used only when the request says there is no spec. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L5] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L74] The diff goes to a uniquely named temp file; diffs over about 3000 lines trigger a chunking offer; step 1 ends with a checkpoint HALT. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L61] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L84] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-01-gather-context.md:L90]

**Layers.** Defaults: `blind-hunter` (at least N findings from diff size, capped at 10; plain list, no severity), `edge-case-hunter`, `verification-gap`, `acceptance-auditor` (full mode only, reviews the diff against the spec). [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L49] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L56] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L57] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L68] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L84] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L98] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L100] [SRC:src/bmm-skills/ship/bmad-code-review/customize.toml:L104] No active layer HALTs `blocked`; failed or empty layers are recorded in `failed_layers`. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-02-review.md:L22] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-02-review.md:L26]

**Triage and persistence.** Severity `high`/`medium`/`low`; buckets `decision_needed` (full mode only), `patch`, `defer` (pre-existing issues, or edits to `CLAUDE.md`/`AGENTS.md`); a finding whose fix edits the spec under review is rejected. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-03-triage.md:L25] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-03-triage.md:L42] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-03-triage.md:L43] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-03-triage.md:L44] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-03-triage.md:L35] With a spec that has Tasks/Subtasks, a `### Review Findings` subsection gets `[Review][Decision]`, `[Review][Patch]` (with `file:line`) and checked `[Review][Defer]` items; deferred findings are appended to `{implementation_artifacts}/deferred-work.md`; without a spec file nothing is persisted. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L21] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L24] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L27] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L30] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L2] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L43]

**Status.** Skipped without `spec_file`; `done` when all decision/patch findings are resolved and no high/medium remain, otherwise `in-progress`; sprint sync writes `development_status[story_key]` and `last_updated`, preserving comments. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L87] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L91] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L92] [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L104] The next-step menu still offers `dev-story`. [SRC:src/bmm-skills/ship/bmad-code-review/steps/step-04-present.md:L124]

## bmad-correct-course

Assesses a significant mid-sprint change across PRD, epics, architecture and UX and produces a sprint change proposal; triggered by "correct course" or "propose sprint change". [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L3] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L3]

- Inputs: PRD and epics in full (whole or sharded) under `planning_artifacts`, `*spec-*.md` specs, and the `bmad:context` block of `AGENTS.md`; missing PRD or epics HALTs. [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L75] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L76] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L79] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L80] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L106]
- Modes: Incremental (each edit HALTs for Approve/Edit/Skip) or Batch. [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L119] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L120] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L185]
- Output: `planning_artifacts/sprint-change-proposal-{date}.md`; recommended approach Direct Adjustment, Potential Rollback or MVP Review; scope Minor (Developer), Moderate (PO/Developer) or Major (PM/Architect). [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L69] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L216] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L217] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L218] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L233] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L271] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L276] [SRC:src/bmm-skills/ship/bmad-correct-course/SKILL.md:L281]
- Approved epic changes update `sprint-status.yaml`; new epics enter at `backlog`; no explicit approval HALTs. ## bmad-retrospective

Reviews a completed epic against its evidence and produces sourced findings, action items and an acceptance decision; supports `-H`/`--headless`. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L3] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L3]

- **Orchestrator interface:** `-H <epic>`; pass the same number to `detect-epic --epic <N>` so the unfinished-story gate is script-backed; epic auto-detection is not an automation contract. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L22] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L22] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L22]
- **Modes:** sprint mode reads `{implementation_artifacts}/sprint-status.yaml`; stories mode takes a spec folder with `SPEC.md`, `stories.yaml` and `stories/<id>-*.md`; a named folder selects stories mode, a number sprint mode. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L41] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L40] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L46]
- **Headless stops:** `story_count` 0 (likely mistyped epic), no detectable epic, `detect-epic` non-zero (`ok:false` JSON surfaced verbatim), multiple candidate folders. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L52] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L53] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L55] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L46] Unfinished stories do not stop a headless run; they are listed under Assumptions. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L57]
- **Evidence:** Phase 2 invokes `bmad-review` with adversarial, edge-case and verification-gap lenses; opt-in Phase 3 uses `bmad-party-mode` and never runs headless. [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L78] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L85]
- **Output:** sprint mode `{implementation_artifacts}/epic-{{epic_number}}-retro-{date}.md`; stories mode `{spec-folder}/RETROSPECTIVE.md` with no sprint-status writes. [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L7] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L63] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L94]
- **Verdict:** frontmatter `verdict` is `accepted`, `accepted-with-open-items` or `rejected`; a non-empty `pending_stories` forces `rejected`; the sprint-status retro key stays `done` whatever the verdict. [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L15] [SRC:src/bmm-skills/ship/bmad-retrospective/references/acceptance-verdict.md:L53] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L21] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L23] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L23]
- **Status update:** `sprint_status.py update` sets `epic-N-retrospective` to `done` (only if the key exists), appends action items with status `open` and ids `epic-<N>-retro-item-<n>-<slug>`, bumps `last_updated`; `--date` must be `MM-DD-YYYY HH:MM`; a headless run never passes `--set-action-status`. [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L54] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L54] [SRC:src/bmm-skills/ship/bmad-retrospective/scripts/sprint_status.py:L471] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L52] [SRC:src/bmm-skills/ship/bmad-retrospective/SKILL.md:L94]
- **Result reading:** `ok:false` means the file was restored untouched; `retro_key_found:false` means the key was absent; `null` means `--set-retro-done` was not passed. [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L57] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L59] [SRC:src/bmm-skills/ship/bmad-retrospective/references/retro-document.md:L60]

```bash
uv run --no-cache {skill-root}/scripts/sprint_status.py detect-epic --file {implementation_artifacts}/sprint-status.yaml --epic <N>
```
