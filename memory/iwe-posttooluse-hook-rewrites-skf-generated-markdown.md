# IWE PostToolUse hook rewrites of SKF-generated markdown before iwe 0.26

During gap-driven `skf-update-skill` runs on cc-primitives and tea-testarch on 2026-09-28, the IWE plugin's PostToolUse hook (`iwe internal claude hook post-tool`, matcher `Write|Edit|MultiEdit|Bash` in the plugin's `hooks/hooks.json`) rewrote the whole `SKILL.md` right after merge §6b's Edit call: it deleted the `[MANUAL]` blocks, re-padded the tables, changed fence openers from ```` ```bash ```` to ```` ``` bash ```` and merged the `## CORRECTION` lines; the runners recovered by re-issuing the content through the shell and `skf-atomic-write.py`, which the hook left alone, and diffing against a pre-run snapshot. That was the editor-tool normalization iwe added in 0.21.0, and iwe 0.26.0 (2026-10-07) removed it: "A markdown document edited with the editor tools in a Claude Code session is no longer rewritten into canonical form behind the edit" (`crates/iwe/CHANGELOG.md` L42 at `iwe-v0.28.0`). In 0.28.0 the hook only schema-checks a `.md`/`.dj` file written by Write/Edit/MultiEdit (`crates/iwe/src/internal/claude/hook/post_tool.rs` L37-L58), and for Bash only schema-checks the keys an `iwe create|update|rename|delete|attach` without `--strict` printed, plus a similar-page check after `iwe create|new`; the schemas here bind only `memory/**`, so markdown under `skf-skills/` and `forge-data/` draws no report. Since 0.25.0 the `[library]` table is `[workspace]` (this repo's `.iwe/config.toml` is now version 4 with `[workspace] path = ""`), and a hook run that loads an older config migrates it in place. On 2026-10-19, with iwe 0.28.0 installed, an Edit-tool change to one line of `CONTRIBUTING.md` left the rest of the file unchanged, its ```` ```bash ```` fences included, so the shell-write workaround is only needed where an iwe older than 0.26.0 is installed; the snapshot-and-diff check stays cheap. The matching SKF health-check finding `fp-47c32b2` was ruled out of scope in the 2026-09-29 triage and never filed upstream: the rewrite came from this local hook, not from SKF, and update-skill `write.md`'s `manual-verify` HALT catches lost `[MANUAL]` blocks.
