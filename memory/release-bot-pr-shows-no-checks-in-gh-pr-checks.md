# Release bot PR shows no checks in gh pr checks

The bot PR that `release.yaml` opens (branch `release/bot/vX.Y.Z-<run_id>-<attempt>`) prints `no checks reported on the 'release/bot/...' branch` in `gh pr checks`, because its required checks run through `workflow_dispatch` of `quality.yaml` on the temp branch, not as pull-request checks. A watcher keyed on `gh pr checks <bot PR>` therefore never sees them pass, and gate 2 times out: on 2026-10-25 the first 3.0.0 `major` dispatch (run 40239814551) failed with "PR #167 was neither approved nor admin-bypass-merged within 30m.", its cleanup step closed the bot PR, and nothing was published. Watch the release run's own steps instead (`gh run view <run> --json jobs`): once "Wait for required status checks" is completed/success and "Wait for PR approval or admin-bypass merge" is in_progress, the bot PR has to be reviewed and admin-merged inside the window. The second dispatch (run 40242635011) did that and shipped 3.0.0 through bot PR #168.

Gate 2 timed out twice more with "PR #N was neither approved nor admin-bypass-merged within 30m." and closed the bot PR with nothing published: the 6.0.0 run 42096776745 attempt 1 (bot PR #215), because the approve-and-watch command blocked on the whole run and never surfaced the PR, and the 7.1.0 run 42476706391 attempt 1 (bot PR #224), because the surfaced PR was not merged inside the window. Both recovered with `gh run rerun <run> --failed`, which needs the `release` environment approved again (gate 1, `gh api -X POST repos/armelhbobdad/bmad-module-ultracode-goal/actions/runs/<run>/pending_deployments` with environment id 16220469047), plus a background poll on `gh pr list --search head:release/bot/vX.Y.Z` that posts the bot PR link the moment it opens. The user merged each bot PR themselves (#216, #220, #225), so surface the PR at once and dispatch or re-run only when the user says they are ready ("We can go", "i am ready to merge"): the 30-minute window starts once the required checks pass, about 9 minutes after the PR opens.
