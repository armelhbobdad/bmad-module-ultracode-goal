# Hand-maintained docs registries invisible to validate-docs-links

Adding or deleting a page under docs/ means hand-editing registries nothing enumerates: docs/index.md (`template: splash`, so it lists pages by hand), the `website/astro.config.mjs` sidebar, README.md's "Learn More" list, the hardcoded llms.txt list in `generateLlmsTxt` in tools/build-docs.js, the mermaid router at the top of docs/troubleshooting.md, and optionally docs/404.md. `validate:docs-links` (`node tools/validate-docs-links.js --strict`) checks the links that are there and cannot notice an omitted entry, so a page missing from a registry passes green: docs/operating-tips.md landed in the sidebar and nowhere else with the gate green, and the llms.txt list lacked the Cross-Session Recall, Knowledge-Graph Refresh and UCG vs bmad-loop pages through v3.2.0. On any page add or delete, grep the tree for the slug and title (`grep -rn 'parallel-mode\|Parallel Mode' --exclude-dir=node_modules .`) and run `npm run docs:build` first: `npm run quality` does not build the site, so the built pass validates whatever old build/site is lying around (it only prints a warnings-only `STALE BUILD` block).

A dead link is caught where a pass reads it. The built pass checks hrefs in build/site and the site links in llms.txt. Since v2.3.0 the source pass reads README.md as well as docs/, CONTRIBUTING.md and changes/README.md (SECURITY.md joined after v3.2.0), so README.md's `[Parallel Mode](./docs/parallel-mode.md)`, which survived the deletion of docs/parallel-mode.md with exit 0 before then, is now reported. The source pass reads inline `[text](target)` links only, and no build reads those four files outside docs/, so an HTML `src=` or `href=` in them (README.md's logo, `<img src="docs/assets/ucg-logo.svg">`) and a reference-style `[label]: url` definition are checked by neither pass: a dead one passes green. README.md and SECURITY.md link the guides by their site URL (`https://armelhbobdad.github.io/bmad-module-ultracode-goal/<page>/`): the source pass maps such a link back to the docs/ page that renders it, and a `blob/main` or `tree/main` repository link back to its file, then checks that the page or file exists and that its `#anchor` matches a heading. Site links are checked against this tree's docs/, but the site shows the latest stable release, so a link to a page or heading added on `main` passes here and 404s, or misses its anchor, on the site until the next stable release deploys it.
