# SKF config keys dropped by the BMAD 6.12.4 update

The BMAD installer 6.12.4 update of 2026-10-17 regenerated `_bmad/skf/config.yaml` with only the core keys (`user_name`, `project_name`, `communication_language`, `document_output_language`, `output_folder`), wrote no `[modules.skf]` table to `_bmad/config.toml`, and left `skf` in `_bmad/_config/manifest.yaml` with `source: unknown` and `npmPackage: null`. Ferris then stopped at activation: `skf-preflight.py` returned `SIDECAR_UNDEFINED` (`sidecar_path is not defined in .../_bmad/skf/config.yaml`). The install answers survive in `_bmad/_config/skf-manifest.yaml` (`skills_output_folder: skf-skills`, `forge_data_folder: forge-data`, `ides: [claude-code]`), and appending `skills_output_folder: "{project-root}/skf-skills"`, `forge_data_folder: "{project-root}/forge-data"`, `sidecar_path: "{project-root}/_bmad/_memory/forger-sidecar"` and `ides: [claude-code]` to the gitignored `config.yaml` restored it. The missing `ides` halts nothing: preflight never checks it, and `skf-export-skill` reads an absent `ides` as an empty list (`load-skill.md`, `shared/data/ide-context-files.json`), so it would write `AGENTS.md` with `.agents/skills/` instead of the `CLAUDE.md` managed section and `.claude/skills/` every earlier export used, flagged only by the note `No IDEs configured in config.yaml: defaulting to AGENTS.md with .agents/skills/.` and an orphaned-context gate on `CLAUDE.md` whose headless default keeps it. After any BMAD update, check `_bmad/skf/config.yaml` for all four keys before running an SKF workflow. Related: [SKF output folder skf-skills, not the default skills](skf-output-folder-skf-skills-not-the-default-skills.md).
