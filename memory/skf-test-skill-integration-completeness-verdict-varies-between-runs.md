# skf-test-skill integration-completeness verdict varies between runs on unchanged text

`skf-test-skill` contextual mode rests each integration pattern's Complete verdict on a single reviewer's judgment (`.claude/skills/skf-test-skill/references/coherence-check.md` §5, "All documented integration points have corresponding code examples"), and `scoring-rules.md` keeps that judgment in the prompt by design, so identical text can pass in one run and fail in the next. The cross-cutting pattern "Deprecated v6 shims are opt-in on fresh v6.12.0 installs (BMM, installer, TEA, BMad Builder)" at SKILL.md L33 of `bmad-module-ultracode-goal-stack` was byte-identical in 1.1.0 and 1.2.0: the 1.1.0 test (run `20260928T185028Z-2049751-e873`) marked it complete, the 1.2.0 test (run `20260929T034547Z-2316573-5bf8`, `forge-data/bmad-module-ultracode-goal-stack/1.2.0/`) marked it incomplete because it applies the fresh-install shim opt-in to bmb but not to TEA's core-ID calls. The score did not move: both reports read "Integration Completeness: 9/10 (90.0%)", because 1.1.0 had flagged a different pattern (tea-testarch + bmad-method-installer, L97), and Combined Coherence rose from 93.97% to 96.0% as Reference Validity went from 57/59 to 48/48; an earlier version of this note said Integration Completeness went from 10/10 to 9/10 and Coherence dropped 4 points, which was wrong, and the 2026-09-29 triage refuted health-check finding `fp-9a21e7a` on that basis. `scoring-rules.md` "## Gap Severity" has no row for an incomplete integration pattern, so the gap was rated Medium by copying the 1.1.0 report's choice; that half is filed upstream as <https://github.com/armelhbobdad/bmad-module-skill-forge/issues/545> (`fp-14a35e9`). 1.2.0 still passed at 98.88 against `--threshold=90` with no fallback, so when comparing stack test scores across versions, expect about one pattern of reviewer variance on coherence, do not treat a newly flagged unchanged pattern as a regression, and keep margin above the threshold.
