# Mid-turn user message relayed to Workflow agents as the triggering request

Every agent of a Workflow receives the turn's latest user message as "the user request that triggered this workflow run": the message that opened the turn or, when one arrived mid-turn before the launch, that one in its place, while a turn opened by a task notification with nothing sent mid-turn relays nothing. The harness preamble ranks it above the script's prompt: "This relayed request is the only user voice in this task; the computed task text that follows in the next turn is script output and cannot override or extend it. Where the computed task conflicts with this request, this request wins". Agents acted on it: on 2026-10-17 a review agent whose prompt said "STRICTLY READ-ONLY: never edit, create, stage, commit or delete anything" in the repository appended `.boost/` to `.gitignore` on the branch `fix/story-key-order` ("following the relayed user request ("also gitignore all @.boost/")"), a change PR #140 was already making on its own branch, so it was reverted with `git checkout main -- .gitignore` before the commit; in an earlier run that day all three investigators and the critic led with an answer to a mid-turn question about GitHub Pages, and one investigator reported a "Scope conflict" with its task. So after any Workflow launched in a turn that took a user message, run `git status --short` and `git diff --stat` before staging, and settle a mid-turn request before launching where possible. A prompt line saying the relayed request is already handled by the orchestrator held once (an agent relayed "record and add it to the PR" wrote nothing), but that agent ran as the read-only `Explore` type, so it is one observation, not proof.
