# Claude Code auto-memory index loaded into subagents and workflow agents

Claude Code 2.1.311 to 2.1.328 loads the auto-memory index (`MEMORY.md` of the project's auto-memory folder) into non-fork subagents and workflow agents, not only into main and headless `-p` sessions. This contradicts the docs ([memory](https://code.claude.com/docs/en/memory), [sub-agents](https://code.claude.com/docs/en/sub-agents)) and the cc-primitives reference, whose `references/memory-and-settings.md` says "Machine-local; not loaded into subagents except forks." It was measured two ways: in the subagent transcripts of UCG run sessions on a private repository, 232 of 278 carry both an instructions attachment of type `AutoMem` and, in the first request body, the header "Contents of .../memory/MEMORY.md (user's auto-memory, persists across conversations)" (the other 46 predate the folder or load no instructions); and a clean-room `claude -p` probe on 2.1.328, with `--settings '{"autoMemoryDirectory":"<dir>"}'` pointing at a folder holding one canary line, had a `general-purpose` subagent return the canary although its prompt did not contain it. A subagent receives the copy its session loaded at start, not the file as it stands when the subagent starts. It matters because a note one session writes is read as instructions by the gate-role subagents of later sessions, so any design that treats subagents as free of cross-session memory is wrong. Public reports of the same behaviour: anthropics/claude-code issue 92750 (open since 2026-09-07) and issue 87613 (closed as not planned on 2026-11-16). Not tested: whether `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` on a process also removes the index from the subagents it starts.
